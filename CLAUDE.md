# aidea lab — портфолио-сайт

Статический сайт (чистый HTML/CSS/JS, без сборки), деплой — GitHub Pages
из ветки `main` репозитория `github.com/yulutik/aidealab`. Автор и
единственный владелец контента — Юлия Колесникова (malina611@gmail.com).

## Структура

- `index.html` — главная (hero, обо мне, портфолио-грид с видео)
- `fashion.html` — раздел Fashion: ряд видео + фотоальбомы
- `css/style.css` — все стили, один файл
- `js/main.js` — i18n (RU/EN), hover-превью видео в портфолио, видео-модалка
- `js/fashion.js` — слайдер видео на fashion.html, карусели фотоальбомов,
  модалка-лайтбокс с поддержкой и фото, и видео-слайдов
- `assets/video/`, `assets/images/` — обработанные медиа, которые идут на сайт
- `_source-photos/` — архив сырых исходников (гитигнорится целиком)

## Workflow с пользователем (важно)

- **Коммит-сообщения пишу сам**, не жду, когда попросят — даже если
  пользователь просто говорит "да"/"коммить и пуш".
- **Разделяю прямые просьбы и вопросы/наблюдения.** "Исправь X",
  "сделай Y", "залей Z" → делаю сразу. "А это не сломается?",
  "это не работает", "можно ли..." → сначала отвечаю/объясняю план и
  trade-off'ы, жду подтверждения, и только потом меняю код.
- Был случай (12.06): перекодировал все видео в 540p без предупреждения
  о просадке качества — это было воспринято плохо. С тех пор любое
  изменение с trade-off'ом (переконвертация, смена разрешения и т.п.)
  сначала проговаривается.
- Внутренние названия фотопроектов/альбомов (например "зелёная сумка",
  "бургунди", "цыпа") используются только в переписке для ориентации —
  **на сайте не отображаются нигде**.

## Конвенция имён файлов

- Фото для карусели Fashion: общий пул `assets/images/fashion-photo-N.jpg`,
  нумерация сквозная и всегда возрастающая (не привязана к альбому).
  Узнать следующий свободный номер:
  `ls assets/images/fashion-photo-*.jpg | sed -E 's/.*-([0-9]+)\.jpg/\1/' | sort -n | tail -1`
- Видео в альбоме (если есть) — `assets/video/fashion-N-full.mp4` /
  `fashion-N-full-mobile.mp4` + постер `assets/images/fashion-N-video-poster.jpg`,
  где N — номер альбома (порядок добавления, не позиция на странице).
- Обработка фото: `sips --resampleWidth 1200 -s formatOptions 82 IN --out OUT`
  (целимся в ~300-700KB на файл, как у существующих).

## Пайплайн обработки видео

Инструмент — **`avconvert`** (встроенный в macOS, не ffmpeg — его в системе нет).
Всегда проверять кодек/разрешение источника перед конвертацией:
`mdls -name kMDItemPixelWidth -name kMDItemPixelHeight -name kMDItemCodecs -name kMDItemDurationSeconds файл`
(если metadata не подхватилась — `mdimport файл`, подождать секунду).

- Десктоп-версия: `avconvert -s SRC -p Preset1920x1080 -o OUT --replace`
- Моб-версия: `avconvert -s SRC -p Preset1280x720 -o OUT --replace`
- Fast-start включён по умолчанию (не передавать `--disableFastStart`).
- AVFoundation-пресеты не апскейлят — если источник меньше целевого
  разрешения, на выходе останется исходный размер (это нормально,
  проверено).
- HEVC конвертируется в H.264 автоматически при прогоне через пресет
  (не PresetPassthrough) — так чинится "не играет в Chrome/Firefox".
- Постер-кадр: `qlmanage -t -s 1200 -o /tmp/outdir файл.mp4`, затем
  `sips -s format jpeg -s formatOptions 80 кадр.png --out poster.jpg`.
- Сырой/необработанный исходник **не коммитится** — переносится в
  `_source-photos/` (там же лежат другие архивные raw-файлы, вся папка
  в `.gitignore`).

## Кеш-бастинг (важно, иначе ловим баг с "пропавшим" функционалом)

`css/style.css`, `js/main.js`, `js/fashion.js` подключены с `?v=N`.
**При любом изменении этих файлов — бампать версию** в `<link>`/`<script>`
и в index.html, и в fashion.html (оба файла грузят style.css и main.js).
GitHub Pages отдаёт их с `cache-control: max-age=600` — без бампа
браузер пользователя может до 10 минут показывать старую версию после
деплоя, что выглядит как "фича не работает", хотя на сервере всё верно
(ровно так один раз и произошло — ушло время на то, чтобы понять, что
это не баг в коде, а кеш).

## Структура одного фотоальбома (fashion.html)

```html
<div class="photo-project"
  data-photos="N,N+1,...">             <!-- без видео -->
  ...
</div>

<div class="photo-project"
  data-photos="N,N+1,..."
  data-video-src="assets/video/fashion-M-full.mp4"
  data-video-src-mobile="assets/video/fashion-M-full-mobile.mp4"
  data-video-poster="assets/images/fashion-M-video-poster.jpg">
  <!-- с видео последним слайдом; .photo-project__play — иконка play,
       показывается в сетке только когда текущий слайд — видео -->
  ...
</div>
```

- Первое фото в `data-photos` = обложка = первый слайд.
- Десктоп (≥900px): инлайн мини-карусель со стрелками внутри карточки.
- Мобиле (<900px): стрелки скрыты, вместо них плашка "ОТКРЫТЬ" поверх
  низа обложки — тап открывает полноэкранную модалку с того же слайда.
- Модалка (`#photo-modal`) — общая на все альбомы, одна на страницу;
  умеет показывать и `<img>`, и `<video controls>` в зависимости от
  типа текущего слайда (см. `js/fashion.js`, `renderAlbum`).
- Порядок альбомов на странице — просто порядок `.photo-project`-блоков
  в разметке; номер альбома (N в комментарии `<!-- Album N -->`) — это
  порядок добавления, НЕ позиция на странице, их намеренно развели,
  чтобы можно было переставлять блоки, не трогая нумерацию файлов.

## Деплой

`git push` на `main` → GitHub Pages переиздаёт автоматически (обычно
1-2 минуты). Домен — `yulutik.github.io/aidealab`, `CNAME`-файла нет.
Если после переименования репозитория Pages "зависает" — помогает
пустой коммит-триггер.
